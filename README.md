# zemail — 邮件分析助手

一个带 Web 界面的邮件分析工具：在页面里输入一个邮箱地址，它会通过 IMAP 从你配置的邮箱中抓取与该地址的全部来往邮件，整理成时间线；之后可以在页面中围绕这些邮件自由追问，聊完再一键让大模型基于邮件和对话生成分析报告（可多次生成、多版本留存，支持导出 Word）。

## 功能

- **专业工作台界面**：左侧边栏（新建目标 + 目标列表）+ 右侧多标签工作区（AI调查 / 分析报告 / 往来邮件，默认落点为对话页；历史记录已并入对话页：在会话消息流顶部点击或向上滚动即可加载更早的会话），响应式布局，手机/平板自适应
- **往来邮件整理**：同时搜索收件箱与已发送文件夹，按时间升序整理双向邮件（发件人/收件人/主题/正文，自动处理中文文件夹名、HTML 正文、编码问题）
- **邮件浏览器**：抓取的往来邮件以表格呈现，支持按方向/关键词筛选，点击单封查看完整内容（HTML 邮件按原排版渲染，沙箱隔离脚本；纯文本邮件按文本显示）；「同步新邮件」增量拉取该目标的新邮件（不影响当前会话），「重新抓取并分析」则全量重建会话
- **AI 报告按需生成**：「新建分析」只抓邮件；在往来邮件页勾选要纳入的邮件（默认全选）后点「开始提问」建立会话；AI调查中觉得需要出报告时，点「生成报告」才基于选中邮件 + 已有对话生成
- **报告版本化**：聊完点「生成报告」出 v1；继续对话后再点「生成新报告」即基于邮件 + 最新对话生成 v2、v3…，报告页可下拉切换任意版本，导出跟随当前选中版本；每版报告记录素材来源（邮件数量与时间范围、对话轮次）及生成时的会话履历，随时可回溯；报告生成指令默认自动注入，也可在报告页展开查看并在生成前修改，每版实际使用的指令随版本存档
- **会话式追问**：分析完成后即可直接提问（如"上次报价是多少""还有哪些没解决的问题"）；会话按目标邮箱隔离，可同时分析多个邮箱、随时切换
- **历史记录**：每次分析与追问自动按目标地址持久化，可随时回看任意邮箱的历史提问与回复
- **报告导出**：一键导出 Word 文档（最新报告 + 历次会话记录，保留标题/列表/表格/加粗格式）
- **用户与权限**：登录访问（Cookie 会话）；管理员默认进入管理控制台（用户管理 + 系统设置），可通过「进入工作台」切换到分析界面；普通用户使用完整分析工作台，各自的分析记录、历史与导出按账号隔离，互不可见
- **其他入口**：`cli.py` 本地终端模式；`server.py` 企业微信自建应用模式（可选，不用企微可忽略）

## 快速开始

```bash
pip install -r requirements.txt
cp .env.example .env   # 然后按下方说明填写
python web.py          # 浏览器打开 http://localhost:8000
```

Web 模式只需要配置**邮箱（IMAP）**和**大模型**两组变量，企业微信相关变量可留空。

### 1. 配置邮箱（IMAP）

- 多数邮箱需开启 IMAP 并使用**授权码/客户端专用密码**（不是登录密码）
  - **企业微信邮箱 / 腾讯企业邮箱**（`imap.exmail.qq.com`，端口 993）：
    1. 管理员在企业微信管理后台确认邮箱的 IMAP/SMTP 服务对你开启；
    2. 你登录企业微信邮箱网页版 → 设置 → 安全登录（或「账户」）→ 生成**客户端专用密码**；
    3. `.env` 中 `EMAIL_ADDRESS` 填完整邮箱地址，`EMAIL_PASSWORD` 填客户端专用密码（不是企微登录密码）
  - QQ 邮箱：设置 → 账户 → 开启 IMAP，生成授权码
  - 163：`imap.163.com`，设置中开启 IMAP 并获取授权码
  - Gmail：`imap.gmail.com`，需开启两步验证后创建应用专用密码
- `.env` 中填 `IMAP_HOST`、`EMAIL_ADDRESS`、`EMAIL_PASSWORD`
- `MAIL_FOLDERS` 留空会自动探测收件箱与已发送；若你的邮箱文件夹名特殊，手动指定（逗号分隔）

### 2. 配置大模型（OpenAI 兼容接口）

填 `LLM_API_BASE`、`LLM_API_KEY`、`LLM_MODEL`。兼容 DeepSeek（`https://api.deepseek.com/v1`）、月之暗面、通义、OpenAI 等。

### 3. 启动 Web 界面

```bash
python web.py    # 默认监听 8000 端口，PORT 环境变量可改；有 waitress 时自动用 waitress
```

首次启动会自动创建管理员账号（默认 `admin` / `admin123`，可用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 覆盖），**登录后请立即在管理控制台的用户管理中修改密码**。之后所有用户由管理员在页面左下角「用户管理」中维护。

生产部署可用 `waitress-serve --listen=0.0.0.0:8000 --call web:create_app`。Web 模式没有企微回调要求，放内网或本机即可，无需公网地址。

### 4. 本地终端模式（可选）

```bash
python cli.py
```

在终端里输入 `分析 someone@example.com` 验证邮件抓取和 AI 分析是否正常。

### 5. 企业微信自建应用模式（可选）

如果希望在企业微信里对话，额外配置企微自建应用：

1. 登录[企业微信管理后台](https://work.weixin.qq.com/) → 应用管理 → 创建自建应用，记录：
   - 企业 ID（`WECOM_CORPID`，我的企业 → 企业信息）
   - AgentId（`WECOM_AGENTID`）与 Secret（`WECOM_SECRET`）
2. 在应用的「接收消息」处设置 API 接收：
   - URL：`http(s)://<你的公网地址>:8000/callback`（需公网可达；内网可用 frp、cpolar 等隧道工具）
   - Token（`WECOM_TOKEN`）与 EncodingAESKey（`WECOM_ENCODING_AES_KEY`）：随机生成后填入 `.env`，再点保存（保存时企微会 GET 验证 URL，服务必须已在运行）
3. 启动企微模式服务：

```bash
python server.py    # 默认监听 8000 端口，PORT 环境变量可改
```

## 部署到服务器（Ubuntu 22.04）

把项目上传到服务器（git clone 或 scp）后，在项目根目录执行：

```bash
sudo ./deploy.sh                    # 使用当前目录代码部署到 /opt/zemail
sudo ./deploy.sh --repo <git-url>   # 或直接让脚本从 git 仓库拉取
```

脚本会自动完成：安装 Python/venv 依赖 → 安装 pip 依赖与 waitress → 生成 `.env`（首次）→ 注册并启动 systemd 服务 `zemail`。首次部署后需 `nano /opt/zemail/.env` 填写配置，再 `systemctl start zemail`。之后重复执行 `sudo ./deploy.sh` 即可更新代码并重启服务；日志用 `journalctl -u zemail -f` 查看。

可选参数：`--dir` 部署目录、`--port` 端口、`--user` 运行用户、`--branch` git 分支、`--skip-apt` 跳过系统依赖安装。

### 一键远程部署（从本机直接发到服务器）

在本机（Git Bash / Linux / macOS）项目根目录执行：

```bash
./deploy-remote.sh    # 部署/更新到 172.16.52.11:8020
```

脚本把当前代码经 SSH 上传到服务器并自动执行 `deploy.sh`（部署到 `/opt/zemail`，服务用户 `zemail`，systemd 服务名 `zemail`），最后做健康检查。首次部署时若本机有 `.env` 会自动上传，服务直接可用；服务器上的 `.env` 与 `data/` 运行数据不会被本机覆盖，需要同步配置时用 `./deploy-remote.sh --push-env`。其他参数（`--server`、`--port`、`--ssh-user` 等）见脚本头部注释。

## 项目结构

| 文件 | 说明 |
|---|---|
| `web.py` | Web 界面服务（Flask）：分析走后台任务 + 前端轮询，追问走同步接口 |
| `static/index.html` | 前端单页（无构建步骤，Markdown 渲染用 marked CDN，加载失败自动退化为纯文本） |
| `server.py` | 企微回调 HTTP 服务（可选模式），立即回 success，后台处理后推送结果 |
| `cli.py` | 本地终端模式 |
| `bot.py` | 指令解析与流程编排（企微服务与 CLI 共用） |
| `wecom/crypto.py` | 回调消息签名验证与 AES-256-CBC 加解密（仅企微模式） |
| `wecom/client.py` | access_token 缓存、消息推送（超长自动分条）（仅企微模式） |
| `mailer/imap_client.py` | IMAP 搜索（收件箱+已发送）、邮件解析与整理 |
| `history.py` | 分析会话历史持久化：按用户分目录（`data/sessions/<用户名>/`）保存问答记录 |
| `exporter.py` | 报告导出：Markdown 转 Word（标题/列表/表格/加粗），生成 .docx |
| `auth.py` | 用户与权限：本地用户库（PBKDF2 哈希）、登录会话、admin/user 角色守卫 |
| `analyzer.py` | LLM 会话管理：邮件材料注入、多轮追问、上下文裁剪、历史落盘 |
| `retrieval.py` | 邮件检索：目录生成与纯 Python 相关度排序（中文 bigram + 类 BM25 打分），追问时按需调阅全文 |
| `summaries.py` | 分层摘要：目录放不下的早期邮件按月由 LLM 压缩为要点，按内容哈希持久化缓存 |
| `config.py` | 环境变量 / `.env` 配置加载 |

## 实现说明

- **Web 异步分析**：抓邮件耗时较长，`POST /api/analyze` 立即返回任务 ID，后台线程抓取邮件并建立分析会话（此阶段不调用模型），前端每 2 秒轮询 `/api/jobs/<id>` 获取进度；追问与报告生成走流式接口（`/api/chat/stream`、`/api/report/stream`），原同步接口保留；报告由用户在对话后手动点「生成报告」触发（`POST /api/report`，基于邮件 + 已有对话生成新版本）。Web 模式的分析会话按目标邮箱隔离（可同时分析多个邮箱并随时切换），另有 `/api/targets`（目标列表）、`/api/emails/<邮箱>`（邮件浏览）、`/api/history`（历史记录）等接口支撑工作台界面
- **企微异步回复**（仅企微模式）：企微要求回调 5 秒内响应，抓邮件 + AI 分析必然超时，所以收到消息后立即返回 `success`，后台线程处理完通过「应用消息」接口推送结果
- **本地缓存**：抓取的往来邮件按目标地址缓存在 `data/emails/`（`EMAIL_CACHE_DIR` 可改，留空禁用），再次分析同一地址时 IMAP 搜索带 `SINCE` 日期条件（最近一封缓存邮件往前回 1 天），只有新邮件才下载正文，重叠部分去重合并；缓存文件含邮件正文，已加入 `.gitignore`
- **抓取范围**：默认不限时间、不限数量（`MAIL_LOOKBACK_DAYS=0`、`MAIL_MAX_RESULTS=0`，可按需改回限制）
- **上下文控制**：正文先剥离回复引用链与签名再截断（默认 2000 字符），IMAP 搜索覆盖 FROM/TO/CC。注入模型的邮件总量默认 24000 字符：放得下则全量全文注入；放不下时改为「全部邮件目录 + 最近若干封全文」，目录也放不下的早期邮件按月生成摘要注入（摘要按内容哈希缓存在 `data/emails/<用户名>/`，内容不变不重复调用模型）。追问时按问题对全部邮件做相关度检索，把命中的未注入全文自动补充进当轮上下文（检索预算为上下文总量的一半，2000~12000 字符）；模型也可按 `REQUEST_EMAIL` 协议主动调阅指定编号邮件的全文（最多 2 轮、每轮 8 封）。多轮对话会把过老的中间轮次压缩为摘要，但始终保留邮件材料
- **会话过期与恢复**：内存中的分析会话默认 120 分钟无操作过期（Web 模式按目标邮箱隔离，企微模式按用户 ID 隔离）；过期或服务重启后，追问/生成报告时会用本地缓存的邮件自动重建会话，无需重新抓取，只有从未抓取过的目标才需要先发起分析
- **历史持久化**：每次分析报告与每轮追问都会写入 `data/sessions/<用户名>/{目标地址}-{哈希}.json`（`SESSION_HISTORY_DIR` 可改），按登录用户分目录隔离，会话过期或重启后仍可在「历史记录」页查看；`重置会话` 只清内存会话，不删历史
- **用户与权限**：用户库存于 `data/users.json`（`USERS_FILE` 可改），密码以 PBKDF2 哈希存储；登录会话签名密钥取 `SECRET_KEY`，留空则自动生成并保存到 `data/.secret_key`；不能删除或降级最后一名管理员，也不能删除当前登录账号
- **运行时设置**：邮件查找时间范围、抓取数量上限、正文截断长度、模型上下文总量、会话有效期这 5 项可在管理控制台的「系统设置」中修改，保存后立即生效并持久化到 `data/settings.json`（优先级高于 `.env`，重启不丢失）

## 注意事项

- 邮件正文会发送给第三方大模型，请评估数据合规性；敏感场景建议改用私有化部署的模型接口（`LLM_API_BASE` 指向内网即可）
- 授权码、Token 等密钥只放在 `.env`（已加入 `.gitignore`），不要提交到仓库
